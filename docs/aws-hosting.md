# راهنمای میزبانی بازارک روی AWS و خرید دامنه

> نوشته‌شده ۲۶ عقرب ۱۴۰۵ (۲۰۲۶-۱۱-۱۷) به خواست صاحب پروژه. قیمت‌ها تقریبی است و از صفحه‌ی رسمی AWS بررسی شده؛ پیش از خرید دوباره ببینید: <https://aws.amazon.com/lightsail/pricing>.
> این سند **پیشنهاد** است؛ هیچ حساب، سرور یا دامنه‌ای هنوز خریده نشده.
> **۱ قوس ۱۴۰۵:** این فایل همان «AWS_DEPLOYMENT» برنامه‌ی کلان است (فایل جدا ساخته نشد تا اسناد تکراری نشود). مقایسه‌ی دامنه/ثبت‌کننده، دو معماری با هزینه، آزمون تأخیر و توصیه‌ی نهایی: `docs/DOMAIN_AND_HOSTING_RECOMMENDATION.md`. با پرداخت آنلاین، سرور ۴ گیگ و پشتیبان‌های جدی‌تر پیشنهاد می‌شود (بخش ۶ همین فایل).

### چرا Lightsail و نه EC2؟
- **قیمت ثابت:** Lightsail سرور، دیسک SSD، IP و حدود ۳ ترابایت ترافیک ماهانه را یک‌جا با یک قیمت دارد. در EC2 هر کدام جدا حساب می‌شود (سرور + دیسک EBS + IP عمومی + هر گیگابایت ترافیک بیرونی) و صورتحساب آخر ماه قابل پیش‌بینی نیست.
- **ساده:** کنسول Lightsail برای کسی که تازه شروع می‌کند خیلی ساده‌تر است (یک صفحه: سرور، IP، DNS، snapshot).
- **راه رشد باز است:** هر وقت لازم شد، از snapshot همین سرور یک EC2 ساخته می‌شود، یا دیتابیس به سرور مدیریت‌شده‌ی جدا (Lightsail Managed Database یا RDS) می‌رود. کد بازارک هیچ تغییری لازم ندارد.

### چه وقت بزرگ‌تر کنیم؟
| نشانه | قدم |
|---|---|
| CPU همیشه بالای ۷۰٪ یا RAM پر | بسته‌ی ۴ GB (حدود ۲۴ دالر) — با snapshot در ۱۰ دقیقه |
| چند صد سفارش در روز | دیتابیس جدا (Managed Database، حدود ۱۵ دالر به بالا) |
| عکس‌ها زیاد و مشتری در ولایات دور | CDN خود AWS (CloudFront یا Lightsail Distribution) برای عکس‌ها — **نیاز به تأیید صاحب پروژه** چون قاعده‌ی «بدون CDN» در `CLAUDE.md` باید عوض شود (این CDN فایل‌های خود ما را نزدیک مشتری نگه می‌دارد، نه فایل بیرونی) |
| چند هزار سفارش در روز | EC2 Auto Scaling + RDS + Load Balancer (بعداً، با طرح جدا) |

## ۲. دامنه

- **`.af` فعلاً پیشنهاد نمی‌شود.** گزارش‌های registrarها متناقض است: بعضی می‌گویند ثبت‌کننده‌ی `.af` (AFGNIC) به‌خاطر تحریم‌ها از registrarهای خارجی پول قبول نمی‌کند، و در ۲۰۲۴ چند دامنه‌ی `.af` معروف به دلیل «پرداخت نشدن» بسته شدند. برای فروشگاهی که نامش سرمایه است، این خطر زیاد است.
- **پیشنهاد:** دامنه‌ی اصلی **`.com`** (همه می‌شناسند، پایدار). **صاحب پروژه `.com` را انتخاب کرد** و `bazarak.com` را می‌خواست (۲۶ عقرب ۱۴۰۵).
- **وضعیت `bazarak.com` (بررسی‌شده ۲۶ عقرب ۱۴۰۵ با RDAP رسمی Verisign):** **آزاد نیست.** از ۲۰۲۰ ثبت شده و تا ۱ اپریل ۲۰۲۷ اعتبار دارد؛ DNS آن NameBright است (معمولاً برای دامنه‌های پارک‌شده یا برای فروش). یعنی شاید فروشی باشد، ولی قیمت دامنه‌های دست‌دوم معمولاً صدها تا هزاران دالر است. `bazarak.net`، `bazarak.shop`، `bazarak.store` و `bazarak.app` هم گرفته شده‌اند.
- **صاحب `bazarak.com` را لازم نیست پیدا کنید:** ثبت‌کننده NameBright است و آدرس `bazarak.com` خودکار به **HugeDomains** (سایت فروش دامنه) می‌رود: <https://www.hugedomains.com/domain_profile.cfm?d=bazarak.com>. یعنی دامنه برای فروش است و قیمت ثابت همان صفحه نوشته شده (من نتوانستم صفحه را باز کنم؛ خودتان ببینید). HugeDomains پرداخت قسطی هم دارد.
- **راه‌ها:** (الف) قیمت `bazarak.com` را در همان صفحه‌ی HugeDomains ببینید؛ اگر گران بود: (ب) یکی از نام‌های **آزاد** `.com` (همان روز بررسی): **`bazarakaf.com`** (پیشنهاد من: «بازارک افغانستان»، کوتاه و بی خط تیره)، `bazarak-af.com`، `shopbazarak.com`، `bazarakstore.com`، `getbazarak.com`. پیش از خرید دوباره بررسی شود.
- **حرف مهم:** هر نامی که خریده شد، نام فروشگاه همان «بازارک» می‌ماند؛ فقط آدرس سایت عوض می‌شود.
- **کجا بخریم:** Route 53 (داخل همان حساب AWS؛ DNS و دامنه یک‌جا) یا Cloudflare Registrar (قیمت تمام‌شده). «Privacy» (پنهان کردن نام و آدرس صاحب دامنه) را روشن کنید.
- اگر روزی `.af` ممکن و مطمئن شد، می‌شود آن را هم گرفت و به `.com` ریدایرکت کرد.

## ۴. قدم‌های راه‌اندازی (وقتی آماده شدید — مرحله‌ی ۶)
1. حساب AWS بسازید (ایمیل، کارت، شماره‌ی تلفن)، MFA را روشن کنید، هشدار بودجه بگذارید.
2. دامنه را بخرید (Route 53).
3. Lightsail ← Create instance ← Mumbai ← Linux ← Ubuntu 24.04 ← بسته‌ی ۲ GB. یک Static IP بسازید و وصل کنید. snapshot خودکار را روشن کنید.
4. DNS: رکورد `A` دامنه و `www` به Static IP.
5. نصب روی سرور (راهنمای قدم‌به‌قدم `docs/nasb-server.md` در مرحله‌ی ۶ نوشته می‌شود): Nginx، PHP 8.4-FPM (با `gd`، `bcmath`، `intl`، `mbstring`، `pdo_mysql`، `zip`)، MariaDB، Composer، Supervisor، certbot.
6. کد از GitHub، `.env`، `composer install --no-dev --optimize-autoloader`، `php artisan migrate --seed --force`، `storage:link`، `config:cache`، `route:cache`، `view:cache`، `icons:cache`، `filament:optimize`.
7. HTTPS با certbot؛ ریدایرکت `http` و `www` به `https://دامنه`.
8. چک‌لیست راه‌اندازی `ROADMAP.md` بخش ۴.

## ۵. از صاحب پروژه لازم است
- ~~کارت بین‌المللی برای حساب AWS~~ — **حل شد:** کارت Visa در دسترس صاحب پروژه هست (۲۶ عقرب ۱۴۰۵). نکته: حساب AWS به نام خود صاحب پروژه باشد و صاحب کارت فقط کارت را اضافه کند؛ ایمیل و رمز حساب و MFA پیش خود صاحب پروژه.

- یک ایمیل همیشگی برای حساب AWS و دامنه (نه ایمیل شخصیِ موقت).

## ۶. تکمیل برای production واقعی (۱ قوس ۱۴۰۵)
- **اندازه:** بازارک با Filament، پردازش عکس (WebP/AVIF) و MariaDB روی یک سرور، **۴ گیگ RAM** را راحت‌تر می‌کشد؛ ۲ گیگ فقط برای آزمایش و ماه‌های اول بی ترافیک.
- **صف و زمان‌بندی (لازم است، نه اختیاری):** `supervisor` برای `queue:work` (اعلان‌ها، رسیدها، پرسش وضعیت درگاه)، و cron `* * * * * php artisan schedule:run` (پاک کردن فایل‌های موقت، **منقضی کردن پرداخت‌های در انتظار**، گزارش تطبیق روزانه).
- **webhook درگاه:** آدرس `https://دامنه/webhooks/hesabpay` باید از اینترنت با HTTPS معتبر در دسترس باشد؛ فایروال فقط ۸۰ و ۴۴۳ (و SSH از IP شما). اگر درگاه IPهای ثابت اعلام کند، در Nginx محدود شود **[بعد از مستندات]**.
- **بازگردانی پشتیبان:** پیش از راه‌اندازی یک بار از snapshot و از `mysqldump` روی سرور موقت (یا لپتاپ) بازگردانده و `php artisan migrate:status` و یک سفارش آزمایشی دیده شود. هر ماه تکرار.
- **بازگشت (rollback) استقرار:** `deploy.sh` پیش از `migrate` یک `mysqldump` می‌گیرد؛ migration فقط رو به جلو؛ کد قبلی با `git checkout <tag>` + `composer install` + `config:cache`؛ هر استقرار یک tag.
- **ایمیل/پیامک:** SES (درخواست خروج از sandbox)؛ پیامک فقط با قرارداد. کلیدهای AWS: کاربر IAM با کمترین دسترسی (فقط S3 پشتیبان و SES)، نه root.
- **گزینه‌ی ب** (دیتابیس مدیریت‌شده + S3/CloudFront) و آزمون تأخیر منطقه‌ها: `docs/DOMAIN_AND_HOSTING_RECOMMENDATION.md`. تغییر `FILESYSTEM_DISK` به S3 برای عکس‌ها بدون تغییر کد ممکن است چون `ImageStore` از `Storage` استفاده می‌کند **[فرض؛ هنگام ارتقا تست شود]**.
